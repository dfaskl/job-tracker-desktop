# Vue + Java 迁移验收、切换与回滚手册

## 当前结论

Vue 3 + Spring Boot 单 JAR 已覆盖旧在线版的核心读取、登录兼容、职位 CRUD、日程、持久会话、备份恢复、AI 配置与邮件识别、管理员后台。公开 Render Demo 仍处于安全展示模式：生产数据库只读，所有测试写入、AI 外呼和管理员操作默认关闭。旧服务应持续运行，直到独立测试库演练和人工验收全部完成。

## 已完成的代码级验收

- Vue 生产构建可被打入 `backend/target/job-tracker-migration-poc.jar`。
- Java 单元与控制器测试覆盖旧密码、AES-256-GCM、数据库 URL、JSON 兼容、职位、日程、会话、备份、AI 端点和管理员权限。
- 老 Node.js 项目的 `npm run check` 与 `npm test` 保持通过。
- GitHub Actions 独立运行 `.github/workflows/migration-poc-ci.yml`，不改动老版本 CI。
- `scripts/verify-deployment.ps1` 仅请求公开状态接口，不读取账号、业务数据或密钥。

## 环境变量分层

| 目的 | 必需变量 | 默认状态 | 说明 |
| --- | --- | --- | --- |
| 生产库只读兼容 | `DATABASE_URL`, `POC_ACCESS_TOKEN` | 已用于原型验证 | 只读检查与旧账号兼容读取 |
| 签名 Cookie | `POC_SESSION_SECRET` | Render 自动生成 | 默认 4 小时会话 |
| 独立测试库写入 | `POC_WRITE_DATABASE_URL`, `POC_WRITE_ENABLED=true` | 关闭 | 地址必须与 `DATABASE_URL` 不同 |
| 测试库持久会话 | `POC_PERSISTENT_SESSION_ENABLED=true` | 关闭 | 只使用独立测试库 `sessions` 表 |
| AI 配置加密 | `POC_ENCRYPTION_KEY` | 未配置 | 需至少 32 字节，不能提交到仓库 |
| AI 外部调用 | `POC_AI_CALLS_ENABLED=true` | 关闭 | 还需测试库与加密配置同时就绪 |
| 管理员后台 | `POC_ADMIN_ENABLED=true` | 关闭 | 还需测试库管理员账号 |

任何时候都不得令 `POC_WRITE_DATABASE_URL` 与 `DATABASE_URL` 指向同一个数据库。当前 `migration-poc/render.yaml` 故意不声明所有写入和外呼开关。

## 独立测试库演练

1. 从生产库做一次脱敏副本或临时克隆，记录创建时间和负责人。
2. 只在迁移 Demo 服务中配置 `POC_WRITE_DATABASE_URL`，先保持 `POC_WRITE_ENABLED=false`。
3. 确认测试库主机、数据库名均与 `DATABASE_URL` 不同，再开启 `POC_WRITE_ENABLED=true`。
4. 用非管理员测试账号完成：登录、创建/编辑/删除职位、时间点与时间段日程、完成/错过/恢复日程。
5. 验证每次写入前生成 `data_backups`，再执行一次备份恢复并核对应用和日程数量。
6. 开启持久会话，验证登录、过期、退出和停用账号后的会话撤销。
7. 使用专用测试 API Key 配置 AI，先保存/清除，再短暂开启外呼并用无敏感信息的测试邮件验证结构化结果；结果不得自动写库。
8. 开启管理员沙箱，验证概览、注册开关、详情审计、普通用户启停及邮箱确认删除；不得对管理员账号执行破坏操作。
9. 关闭 `POC_AI_CALLS_ENABLED`、`POC_ADMIN_ENABLED` 和 `POC_WRITE_ENABLED`，保留测试报告和失败截图。

## 上线前人工验收

- 以已抽查的 103 条记录为基线，再做应用总数、事件总数、状态分布与最近更新时间的自动对账。
- 选择至少 10 个包含时间线、跨天日程、已完成/已错过事件和备注的复杂样本逐项核对。
- 确认生产环境的 Java 21、内存、连接数、日志保留和 Render 健康检查 `/healthz`。
- 确认 Cookie 域名、HTTPS、SameSite、管理员邮箱、注册策略和 AI 域名白名单。
- 记录切换负责人、观察人、开始时间、最长观察窗口和明确回滚阈值。

## 推荐切换方式

1. 保持旧 Render 服务 `job-tracker-web` 在线，不删除、不改数据库结构。
2. 新建独立的 Vue+Java 生产服务；先以独立 URL 做只读和登录验收。
3. 在低峰期短暂停止旧服务写入，创建最终数据库备份并记录最后更新时间。
4. 将新服务切换到正式数据库连接方案后，先对单个内部账号开放，再逐步扩大流量。
5. 观察至少 30 分钟：健康检查、登录错误率、数据库错误、写入量、备份生成和页面关键流程。
6. 只有验收人确认后才切换主域名；旧服务至少保留一个完整观察周期。

本手册只是切换准备，不授权当前迁移 Demo 对生产库写入，也不授权自动修改域名或停止旧服务。

## 回滚触发条件

- 登录或会话持续失败；核心页面无法加载。
- 新增/编辑/删除后出现数据丢失、重复或 JSON 结构变化。
- 数据库错误率、响应时间或连接数明显恶化。
- 备份未生成、恢复校验失败，或管理员权限边界异常。
- AI 请求出现密钥泄露、内网访问或非预期自动写入迹象。

## 回滚步骤

1. 立即停止新服务入口的写请求，不删除新服务日志或数据库记录。
2. 将流量或主域名切回仍在线的旧服务。
3. 以最终备份时间为边界，对比新旧服务观察窗口内的写入；由负责人决定逐条补录或事务性恢复。
4. 不要直接用旧备份覆盖整个数据库，除非已确认观察窗口内没有合法新写入。
5. 保存错误日志、受影响账号和操作时间，修复后重新从独立测试库演练开始。

## 公开部署验收

在仓库根目录执行：

```powershell
pwsh -File migration-poc/scripts/verify-deployment.ps1
```

脚本通过只表示服务和公开状态接口可用，不代表独立测试库写入、AI 外呼或生产切换已经获准。
